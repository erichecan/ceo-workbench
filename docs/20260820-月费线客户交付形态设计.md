# 月费线客户交付形态设计 · 2026-08-20

**为什么有这份文档**：Eric 要求"开试用前先把交付产品形态定清楚"——客户参与哪些步骤、不参与哪些、能看到什么、在哪里看、要不要提醒、客户怎么评价好坏、试用期间能不能看到收益。这份文档在开 EmbedMyReviews 免费试用**之前**把这些决策做出来。试用只用来验证"工具技术上能不能做到"，不是从试用开始才现想产品该怎么给客户用。

---

## 一、先说清楚一个限制：官网看不到客户端 UI 细节

WebFetch 了 embedmyreviews.com 首页和 `/features` 两次，营销页只讲卖点，没写清楚终端客户登录后的具体界面、通知机制、AI 回复审核由谁做——这类信息只有实际登录试用账号才能看到。

所以下面不是"照抄工具默认流程"，是**我们自己决定要不要用工具自带的客户门户，还是完全自建交付方式**——这个决策权在我们手上，不需要等工具功能定了才能定。

## 二、交付模式选择：代理全权托管，不给客户开自助门户

参照 print-main / veggie 现有关系模式——客户不登录我们的内部系统，只接收交付结果。第一版月费产品沿用同一模式：

**客户不拿任何后台账号，我们（运营方）登录 EmbedMyReviews 后台完成一切操作，客户只通过邮件收到我们生成的报告和关键提醒。**

理由：小商户客户不是技术用户，多一个要学的工具后台=多一份流失风险；工具本身"unlimited users"不额外收费，如果客户后续主动要求可见性，随时可以加开一个只读账号，成本为零，不需要现在就决定。

## 三、逐条回答

### 1. 客户参与哪些步骤 / 不参与哪些步骤

**客户必须做的（无法代劳，只有一步）**：把 Google Business Profile 的"管理者"权限邀请给我们的运营账号（或配合走一次 OAuth 授权）。工具功能页确认了这是硬性要求（"Generate, edit, and post directly to Google"）。大约 5 分钟，一次性。

**客户不用参与（我们代劳）**：监控新评价、生成回复草稿、**审核并发布回复**（由我们审核——客户找我们做这件事，本来就是为了不用自己盯）、查看排名追踪数据、制作月度报告。

### 2. 客户能看到什么，在哪里看

不开工具原生后台账号。客户看到的是我们自己出的东西：**每月一份邮件报告**，固定包含：本月新增评价数、平均分变化、我们代发的回复摘要、本地排名位置变化（如有有意义的排名词）。

### 3. 是否需要提醒，提醒什么

需要，但提醒的对象**首先是我们自己**，不是直接转发给客户：
- 出现新差评（如 ≤3 星）→ 我们收到提醒，尽快审核回复稿并发布；差评往往涉及具体客诉，视情况单独知会客户
- 月度报告生成 → 发给客户
- 客户侧暂不加短信通道，先用邮件，成本已含在订阅费里

### 4. 客户如何评价这个产品好坏

不让客户自己去解读工具原始数据，月报固定用四项指标：评价数量净增长（月对比）、平均评分变化、回复覆盖率/时效、本地排名位置变化。

### 5. 客户能看到试用期间的收益吗——这里要说一个诚实的限制

**不能，而且不该承诺能。** 14 天免费试用能证明的是"工具技术上真的能连上 GBP、真的能监控评价、真的能生成合理回复"——这是**能力验证**，不是**效果验证**。评价数量和本地排名这类指标，14 天内几乎不会有肉眼可见变化；如果对客户承诺"试用期间就能看到收益提升"，大概率是空头支票，会立刻伤害这个客户关系的可信度。

诚实的定位：
- 试用期间给客户看的是**基线快照**——不是收益，是现状：当前有多少评价、平均分多少、本地排名在哪、跟同行比处于什么位置。很多小商户从没系统看过自己的评价全貌，这个快照本身就有销售说服力，不需要等收益出现。
- 承诺的是"付费第一个月起开始产生可衡量的变化"，**不是"试用期间就有收益"**——报价谈判时要把这条讲清楚，避免客户后续拿"怎么用完试用也没见涨"来砍价或流失。

## 四、试用要验证的技术清单（对应战略文档第八节遗留的核实缺口）

- [ ] GBP 管理者授权流程是否顺畅
- [ ] 能否真实拉取到历史评价列表和评分
- [ ] AI 回复草稿质量是否可用（不需要大改）
- [ ] 排名追踪（"Local Search Grid"）能否显示出有意义的数据
- [ ] 月度报告/PDF 导出的实际长相是否达到能发给客户的水准
- [ ] **有没有"主动邀请客户留新评价"功能（review request，不是回复已有评价）**——有的话，触发方式是什么（服务完成后自动发短信/邮件？还是只能手动逐个发？是否需要接客户的 CRM/POS 才能拿到"服务完成"这个时间点？）。**这条紧迫度最高**，理由见下方补充说明

### 补充说明：为什么这条要单独强调

Eric 问过"Podium 说90天评价量涨3倍是怎么做到的"，查证后确认：这个数字的驱动力是**服务完成瞬间自动发短信邀评**（短信打开率~98%），Podium 自家数据显示"自动邀评商户比靠人工开口问的商户多收到3.4倍评价"——**3倍这个卖点靠的是邀评自动化，不是评价监控/回复**。

我们目前对 EmbedMyReviews 已确认的功能清单（监控评价、AI 回复草稿、看板、报告）里**没有一条是主动邀评**。如果试用验证下来这个工具没有邀评功能，或者有但依赖接客户 CRM/POS 才能触发（小商户大概率没有标准化 CRM，接不上），那我们能对客户讲的"收益故事"就要收窄——只能讲"把已产生的评价管理好、回复及时、口碑不失分"，讲不出"评价数量会涨"这类更有销售冲击力的承诺，报价和话术都要相应调整。
