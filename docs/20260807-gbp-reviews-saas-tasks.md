## 执行规则（每次开工先读这里）

**台账是进度的唯一真相，对话不是。**

一个周期 = 一个可交付单元：
```
读台账 → 取第一个未完成 → 做 → 验证 → 提交 → 回写状态（含 commit hash）→ 下一周期
```

**硬停止条件**（满足任一条立刻停下来问）：
- 台账已无未完成条目
- 同一个问题连续 2 次没修好 —— ⛔ 不要试第 3 次
- 需要外部账号 / API Key 而项目中没有配置
- 需要部署到 GCP（必须用明确的 Project ID，绝不猜测）
- 台账与实际状态对不上

**本项目特有的红线**（写进每个涉及客户 GBP 的任务）：
1. 不做评价门控（不允许"先筛满意度再分流"的任何形式）
2. 不代写评价
3. 改客户 GBP 前必须有快照；每个 GBP 每天写操作 ≤ 2 次
4. 短信索评必须有明示同意存证

## ⚠️ 重大修正（2026-08-07，做 T1 时发现）

**规划文档 §2.2 写的「两道审批门」是错的。实际只有一道。**

| | 原规划的说法 | 实际情况 |
|---|---|---|
| 门 1 | GBP API Basic Access 申请 | ✅ 存在，且是**唯一**的门。官方口径 14 天内审完 |
| 门 2 | OAuth 敏感权限验证（域名+隐私政策+英文演示视频，3–5 工作日） | ❌ **不存在**。Cloud Console 把 `business.manage` 归为 **non-sensitive**，验证中心根本没有针对它的提交入口 |

**好消息**：不用拍演示视频，不用 CASA 安全评估，省掉 $500–4,500/年 + 年度复审。

**坏消息**：批准前，外部用户走 OAuth 授权会被 **403 access_denied** 硬拦，而且因为 Console 认为它"非敏感"，**连申诉/提交验证的入口都没有**——只能等 Basic Access 批下来，没有第二条路。已有开发者在 Google 官方论坛报告卡在这个死循环里。

**但官方 FAQ 给了另一条授权路径，这条最有价值：**

> 商家把你的 Google 账号**加为 Manager（管理员）**，你就能用自己的凭据直接调 API，**完全不需要 OAuth**。

这一条同时解决了三个问题：外部用户 403、100 个测试用户上限、refresh token 7 天过期。而且对 GTA 华人小商家来说，"把权限给你"比"点一个全英文的 OAuth 授权页"更自然、成功率更高。

⚠️ **注意边界**：Manager 路径替代的是 OAuth，**不替代 T2 的项目级审批**。API 访问权是按 GCP 项目授予的，没有 T2 一切免谈。

**其它顺带确认的事实**（来自官方 FAQ）：
- 批准后一次性拿到**八个 API** 的默认配额：Account Management、Business Information、Lodging、Place Actions、Notifications、Verifications、**Q&A**、Performance
- **Q&A API 确实存在**（Q3 部分解答：存在性已确认，写入能力仍待实测）
- 评价（Reviews）和发帖（Local Posts）**不在这八个里**——它们仍在 v4 老接口上，需单独确认
- 测试不允许建假的门店资料，只能用真实客户或自己公司的资料

### 已知的演示数据特性

`prisma/seed.ts` 的 `NOW` 固定为 `2026-08-07T12:00:00Z`，而界面的"近 30 天"窗口用真实时间。
随着真实日期推进，最老的数据会逐渐滑出窗口（已观察到：7 月第 1 周的索评批次在 8/8 已落在窗口外）。
演示前重跑 `npx tsx prisma/seed.ts` 即可。若要长期演示，需把 `NOW` 改为相对当前时间计算。

### 对现有规划的三条硬冲击

1. **定价假设被推翻。** U12 里我建议社媒加购 +$149/月（FB+IG）。实际：Birdeye 同类能力 **$50/月**，Merchynt 连**内容生产**一起给才 **$99/月**。+$149 只卖分发管道，报不出去。

2. **档位命名与价格带撞车。** Birdeye 的三档就叫 Starter / Growth / **Dominate**（$299/$349/$449 USD）。我们的「区域压制」CAD $549 ≈ USD $400，正落在 Birdeye Dominate 区间，但对方是纯产品、我们是产品+人工。**要么价格下来，要么把人工服务的价值讲明白。**

3. **功能差异化不成立。** 我们做的「多平台分发 + 互动收件箱」是这个赛道的**标配**，不是卖点。可守的差异化只剩：**中文交付、本地华人服务、微信触达**——都不是产品功能，是服务形态。

### 可直接抄的两个点

- **Review Sharing**（Birdeye）：把好评自动转成社媒帖子。**我们已经拥有全部评价数据**，实现成本极低，是现成的内容来源——这条直接缓解「商家没东西可发」的痛点。
- **外部审批流**（Birdeye）：把内容路由给商家本人审批。华人小商家对「你替我发了什么」的控制欲很强，这条比多平台分发更可能是刚需。
