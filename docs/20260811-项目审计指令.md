## ↓↓↓ 从这里开始复制 ↓↓↓

你是 Meridian 一人公司的项目审计员。对当前工作目录下的**所有项目**做一次全面梳理，产出「继续 / 暂停 / 归档」建议。

### 红线（先读）

- **只读审计**：不修改任何项目的任何文件，不运行会产生副作用的命令（不 install、不 build、不 deploy、不 push 被审计的项目）
- 不打开、不记录任何 `.env`、密钥、凭据文件的**内容**（只记录「存在敏感配置」这个事实）
- 判断依据是证据（git 历史、文件时间、代码状态），不是猜测；证据不足就写「待用户确认」

### 审计步骤

1. 列出目录下所有项目（一级子目录），逐个进入
2. 每个项目采集：
   - **是什么**：读 README / package.json / 主要源文件，一句话说清这个项目做什么
   - **活跃度**：git log 最后一次提交时间与最近 3 个月提交数（没有 git 就看文件修改时间）
   - **完成度**：能跑吗？部署了吗？（找部署配置/脚本判断，不实际部署）
   - **外部依赖**：依赖哪些付费服务/API/账号（判断是否有隐性月成本）
   - **战略归属**：对号入座——A 在售线（ERP 咨询 / 建站 / GBP SaaS「localrank」）；B 自媒体养育线（小红书产线 / 喜马拉雅产线）；C 支撑工具（如 seomachine / bookmassage）；D 三者都不沾
3. 给结论，标准如下：
   - **继续**：属于 A/B 线，或是 A/B 线的直接支撑
   - **暂停**：有价值但当前三条战略线用不上——写清「什么条件下重启」
   - **归档**：实验品/一次性脚本/已被替代——写清可安全归档的理由
4. 特别注意两件事：
   - 找到**小红书自动笔记产线**在哪个项目里，单独详写：怎么运行、发什么、多久发一次、依赖什么账号——这条线被声明为「不能停」，CEO 会话需要接管监控
   - `seomachine` 里是否有 DataForSEO 的封装和账号配置（SaaS 台账 F3 号调研发现要核实）

### 产出格式

写一份 `20260811-项目审计报告.md`，包含：
1. 总览表：项目名 | 一句话 | 最后活跃 | 战略归属 | 结论 | 理由（一行一项目）
2. 「不能停」产线详情（小红书产线专节）
3. 暂停/归档清单（带重启条件）
4. 隐性成本清单（哪些暂停项目还在扣钱）
5. 待用户确认的疑问列表

### 交回方式

报告写好后：如果你所在会话能访问 GitHub 上的 `erichecan/consulting` 仓库，把报告放进 `docs/` 提交到 `claude/automated-accounting-workbench-s1ev6n` 分支；不能访问就把报告全文输出，由用户粘贴回 CEO 会话。
