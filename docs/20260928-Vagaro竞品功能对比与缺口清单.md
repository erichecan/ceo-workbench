# Vagaro 竞品功能对比与 booking-app 缺口清单

调研对象：https://www.vagaro.com/en-ca/pro/{calendar,payroll,memberships,inventory,customer-tracking,notifications,email-marketing-software,text-marketing-software}
对比对象：/Volumes/datacenter/04-eric/AIcoding/webproject/booking-app（当前代码库实际状态，非文档声称状态）

## 一、逐模块对比

### 1. Calendar 日历/预约

| Vagaro 功能点 | booking-app 现状 |
|---|---|
| 按服务/日期/时间自定义员工可用性 | 无 |
| 处理时间/午餐/会议 buffer | 无 |
| 双预约（同时段多预约） | 无冲突检测，理论上不阻止，但无该产品概念 |
| 私人任务阻挡时段 | 无 |
| 循环预约 | 无 |
| 预约变更自动通知客户 | 无（见 Notifications） |
| 颜色编码/多主题/深色模式 | 有（按员工 `calendarColor` 着色） |
| 老客户自动识别与召回 | 无 |
| 多员工分栏排班视图 | 无（日视图单列展示所有预约） |
| 拖拽改期 | 无 |
| 月视图/列表视图 | 无（仅日视图+周视图） |
| 多资源调度（房间/设备） | 无 |
| 预约状态流转 | **有**（BOOKED/CONFIRMED/ARRIVED/STARTED/COMPLETED/NO_SHOW/CANCELLED，比 Vagaro 页面展示的还细） |

**结论：核心 CRUD 有，运营效率类功能（冲突检测、拖拽、周期预约、多员工视图）基本没有。**

### 2. Payroll 工资

Vagaro：预订→薪酬一体化、工时追踪、自动税务合规、自定义提成、直接存款/支票发薪、PTO、员工自助端。
booking-app：**几乎为 0**。仅 `TeamMember.commissionRate` 字段存在于 schema，全代码库未被任何逻辑读取。

### 3. Memberships 会员

Vagaro：会员等级自定义、次卡/套餐、自动扣费、积分、会员折扣、实时报表。
booking-app：**0**。`Sale` 模型有 `walletAmount`/`pointsEarned`/`pointsRedeemed`/`couponAmount` 等占位字段和 `Workspace.pointsPerEuro`，但未接入任何业务逻辑，纯预留。

### 4. Inventory 库存

Vagaro：商品管理（条码/图片/变体）、实时库存、智能采购单、补货预测、低库存提醒、BNPL(Affirm)、零售积分、AI 生成商品文案。
booking-app：**0**。无 Product/Inventory/Supplier 相关模型或代码。

### 5. Customer Tracking 客户追踪

| Vagaro | booking-app |
|---|---|
| 统一档案（偏好/备注/历史） | 部分：`notes` 字段有，消费/预约历史未关联展示 |
| 渠道来源追踪+绩效对比 | 极简：仅 `Appointment.channel`（ONLINE/OFFLINE），无客户级来源标记，官网 features 页自己写明"按渠道细分统计"是未做的定制项 |
| 客户分层/标签 | 无 |
| 客户留存率统计 | 无 |
| 支付方式存储 | 仅交易级 `Sale.paymentMethod`，非客户档案属性 |

### 6. Notifications 通知

Vagaro：邮件+短信自动提醒、预约确认、App 内推送、双向聊天、商家端操作提醒。
booking-app：**基本为 0**。无 nodemailer/twilio/推送依赖，"实时"提醒是侧边栏每 60 秒轮询 `pending-count` 接口刷新一个数字角标，无弹窗/声音/邮件/短信。官网 features 页已明确写"短信/邮件自动提醒"需接入 Twilio 等（未做）。

### 7. Email Marketing 邮件营销

Vagaro：拖放编辑器、模板库、AI 文案、自动化触发、打开率追踪。
booking-app：**0**。`components/marketing/` 只有产品官网导航组件，与营销邮件无关。

### 8. Text Marketing 短信营销

Vagaro：促销群发、生日祝福自动发送、空位提醒。
booking-app：**0**。

## 二、缺口分级（按"构建成本 vs 对成交的影响"，我的技术判断）

**A 类·成本低、影响预约体验、建议优先补：**
- 冲突检测（同员工同时段不能重叠）—— 半天工作量，防止真实使用时出丑
- 月视图/多员工分栏视图 —— 提升可演示性，Vagaro 主打这个
- 客户详情页关联历史预约/消费记录展示 —— 数据已在库里，只是没 UI 呈现

**B 类·成本中等、需要外部账号才能跑通：**
- 邮件/短信预约提醒（需要 Resend/SendGrid + Twilio 账号，属于第六节"需要没配置的外部账号"，要先问你要不要开）
- 拖拽改期、周期预约

**C 类·成本高、属于独立子系统，不建议现在做：**
- Payroll：涉及税务合规、发薪渠道对接，Vagaro 这页面背后是加拿大/美国工资税法规引擎，做一个不合规的版本比不做风险更大
- Inventory：完整进销存 + BNPL(Affirm) 分期，是另一套电商库存系统
- Memberships：自动扣费需要接支付网关的订阅计费能力，比一次性收款复杂一个量级
- Email/Text Marketing：营销自动化平台本身就是一个产品品类（类似 Mailchimp），照搬等于重新做一个 SaaS

C 类四项加起来的工作量，规模上不是"补几个功能"，是再造一个 Vagaro。
