# 预约系统:技师排班 + 完整字段 + 卡片分发追踪 —— 任务台账

> 背景:店主在小红书私信里回复顾客预约后,回到 `portal.js` 点"记下这个预约",发现:
> 记录字段不全(无姓名/电话/项目/渠道)、系统里压根没有"技师"概念(无法看排班)、
> 卡片是静态图片,发出去之后系统不知道会不会撞车。三轮确认后的范围见下。
> 每条任务独立可验收,做完一条就回写状态,不要求做完全部再验收。

## 任务清单

- [x] T1 schema-staff:`storage.js` 新增 `staff` 表(id/lead_id/name/active/sort_order/created_at)+ `listStaff/addStaff/deactivateStaff`。
  验收:temp db 插入两个技师、列出、停用一个后 listStaff(activeOnly) 只剩一个。
- [x] T2 schema-bookings-cols:`bookings` 表迁移新增 `customer_name/phone/service_item/channel/staff_id` 5 列;`addBooking()` 签名从位置参数改成对象参数;`listBookings()` 带出新列。
  验收:旧库跑 `open()` 迁移不报错;`addBooking` 传新字段能写入,`listBookings` 能读出。
- [x] T3 conflict-by-staff:`booking.js` 的 `getFreeSlots`/`storage.js` 的 `bookingsOn` 冲突判断按 `staff_id` 分组——指定了技师只跟同技师比对,没指定技师按店铺整体判重(单人店行为不变)。
  验收:两个不同技师同一时段互不冲突;同技师同时段冲突;都不填技师维持老逻辑。
- [x] T4 card-sends:`storage.js` 新增 `card_sends` 表 + `recordCardSend/findConflictingSends/resolveCardSend`。
  验收:插入一条发送快照后,对重叠时段的新预约能查出冲突;`resolveCardSend` 后不再命中。
- [x] T5 portal-form:`portal.js` "记下这个预约"表单加姓名/电话/项目/渠道(下拉,默认小红书)/技师(有技师才显示)字段,接入新版 `addBooking`。
  验收:浏览器提交后 DB 里能看到新字段值;没有技师的 lead 不显示技师下拉。
- [x] T6 portal-send-and-warn:`portal.js` 卡片区加"我发了这张卡"按钮(选填备注)→ 落 `card_sends`;记预约时若命中冲突,页面顶部醒目提示 + "标记已处理"按钮。
  验收:先标记发送,再对重叠时段记一笔不同技师/不同顾客的预约,页面出现冲突提示;点"标记已处理"后消失。
- [x] T7 schedule-view:`portal.js`(以及 `card-admin.js`)新增 `/schedule` 页面,按天网格展示各技师忙闲时段(横轴技师、纵轴时间);单人店退化成一列。
  验收:浏览器打开能看到网格,预约落在正确的技师列和时间格里。
- [x] T8 card-admin-parity:`card-admin.js` 同步 T1/T2/T5(技师管理、预约表单字段),保证内部工具跟店主端数据口径一致。
  验收:在 card-admin 记一笔带技师的预约,portal 那边能看到同一条。
- [x] T9 bugfix-slug:修 `portal.js` slug 计算漏了"品牌名为空时用昵称兜底"(跟 `card.js`/`card-admin.js` 对齐);`card-admin.js` 保存 `card_meta` 时若 slug 因改名变化,删除旧的卡片输出文件。
  验收:清空品牌名场景下 portal 卡片预览不再 404;改店名后旧 png 文件被删除。
- [x] T10 regression:跑 `npm test` 全绿;手动过一遍验证清单(增删改查、多技师排班、卡片重新生成);写完成情况回这份台账。
