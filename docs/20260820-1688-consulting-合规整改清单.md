## 二、consulting 仓库（13 条）

**背景**：`app/[locale]/*` 是 `middleware.ts` 路由匹配下确认可达的生产路由；非locale版本（`app/about|contact|page|cases/page.tsx`）静态推断大概率不可达，但仍存在于源码/构建产物中。

### 🔴 最高优先级（整站身份级虚构）

**1. `app/[locale]/about/page.tsx:4-23,65-88`** — 3名虚构团队成员详细履历
James Hartley、Sarah Chen、David Okafor，全公司零客户零收入佐证。
→ 建议：**A 下线**该页面或团队板块，直到有真实团队信息可放；或 **C** 明确标注"演示网站，团队信息为示例"（但既然是要接真实询盘的公司门面，不建议C）。

**2. `app/[locale]/contact/page.tsx:7-18`** — 虚构伦敦Mayfair办公室（"12 Grosvenor Square, London W1K 6JP"/"+44 20 7946 0321"）和香港中环办公室（"Unit 2801, Two IFC"/"+852 2345 6789"）
`020 7946` 是英国Ofcom预留的虚构号码段——技术上可证伪。
→ 建议：**A 下线**这两个虚构地址/电话，改为真实可联系方式（哪怕只有一个邮箱）。

**8. `messages/en.json`（`zh.json`镜像）约95-197行（`cases.items`）** — **10个完全虚构的案例研究**，含精确伪造指标
如 `ecommerce-wms-peak-readiness`：吞吐量+28%，准确率99.4%；`wholesale-tms-freight-savings`：运费-22%，配送+15%，满意度4.8/5；`wholesale-distribution-network`：年节省$1.4M；另有6个。展示在首页（`app/[locale]/page.tsx:11-36,377-419`）和完整案例页。
→ 这是consulting站最大的单项虚构，直接支撑了公司信誉的核心卖点。建议：**A 下线**全部案例板块，或 **B** 改写为不含具体客户名/精确百分比的能力说明（"我们能做什么"而非"我们做过什么"）。

### 🟡 高优先级

**3. `app/contact/page.tsx:6-21`**（非locale版）— 同一虚构公司但**另一套完全不同**的假地址/电话/邮箱，与条目2内部矛盾（本身就是虚构的证据）。
→ 大概率生产不可达，视为**仓库清理**项：建议直接删除这个非locale版本文件（避免以后误上线或造成困惑）。

**6. `app/[locale]/page.tsx:4-9`** — 首页统计数字 `40+`/`18%`/`99.4%`/`90d`，0真实客户支撑。
→ 建议：**A** 删除或 **B** 改写为无数字的定性描述。

**7. `app/page.tsx:4,7`**（非locale）— "40+ Engagements delivered"、"94% Client retention rate"，与0客户数学上矛盾。
→ 同条目3，建议直接删除该非locale文件。

**9. `app/cases/page.tsx:120,124,235`**（非locale）— 重复的虚构内容（"Invoice Disputes Down 94%"、"40+ Engagements"）。
→ 同条目3，建议直接删除。

**10. `messages/en.json:240-245,311-315,382-387`**（`zh.json`镜像）— 仓储/运输/电商三个服务页各一段虚构"stats"板块，数字复用自条目8的案例（99.4%、32%、22%）——模板化伪造的证据。

### 🟡 表单数据丢失（真实询盘正在被丢弃）

**4. `app/[locale]/contact/page.tsx:28-33,69-96`** — 表单收集姓名/邮箱/公司/留言；`handleSubmit` 只是 `setTimeout(1200ms)` 后显示成功；全仓零个 `route.ts` 接收端——**100%提交数据丢失**。

**5. `app/contact/page.tsx:27-33`**（非locale）— 同类假表单（`setTimeout(800ms)`）。

**12. `app/[locale]/contact/page.tsx:128-142`** — 无法兑现的承诺："一个工作日内回复"、"每季度限量接单"，而0客户+表单不可用。
