## 二、建站/系统线的差异化（v2 逻辑不变，照录）

中小企业不知道自己需要什么网站、什么系统，只知道「我想线上宣传」「我想获客」。
**不做模板报价**——每条线索，回给它的是一个针对这个行业、这个人、这个生意的咨询式定制 demo。
先诊断，再给看得见的门面（demo），报价在诊断之后。定制 demo 边际成本≈token，这是一人+AI 公司才有的经济学。

1688 的 demo 中心已经是这套打法的现成基础设施——**这条线目前的问题不是没有工具，是没有把工具用起来对外跑**。

## 八、当前待决策：月费线二选一（CEO 推荐）

原始问题（家底盘点 §4）：转售白标（GoHighLevel+Local Falcon 类，~$122 USD/月，人工交付，毛利与客户数据在别人手里）**或**移植 seomachine 计费层自研（代码完整但零验证：从未 npm install/构建/无 migrations）。

**CEO 推荐：先走白标转售，不先自研。**

理由：
- 公司现在**还没有一个月费线的真实付费客户**——在没验证「有没有人愿意为评价管理付钱」之前，把人时投入到迁移一套零验证的计费系统上，是在给一个未知需求造精装修的收银台
- 白标路径把「今天能不能收到第一笔月费」和「用什么技术收」解耦：先用别人的收银台验证需求，需求验证通过（哪怕只有 1-2 个真实付费客户）之后，再迁移 seomachine 的计费层换取长期毛利——那时候值得投入的确定性更高
- 唯一代价是白标月固定成本 ~$122 USD，且客户数据在第三方——这个代价只有在真正获得客户之后才需要承担，验证阶段可以先谈意向不落地收款
- 风险不对称：白标路径试错成本是「多付一份 SaaS 月费」；自研路径试错成本是「工程人时投入一个从未验证过的部署链路，还可能一分钱没收到」

**这是推荐，不是决定**——按第四节规则，这类分叉需要你拍板。若同意，我下一周期直接推进白标接入；若你倾向自研，也请明说理由，我会重新评估。
