## 一、三条线（按收入性质分，不按行业分）

### 1. 资产线 —— 被动收入（已在产出，方向是放大不是新建）

- **喜马拉雅**：已有课程、已有少量被动收入。做的事：现有账号扩容、下一门课、周更产线
- **小红书（职场类内容账号）**：同源内容，养账号
- **新增：「AI 当 CEO」账号**（CEO 决策，理由见第三节）
- 资产线的双重产出：**被动收入** + **职场咨询的线索**

### 2. 现金流线 —— 项目制收入

- **职场类咨询**：由资产线内容带来，认知变现
- **建站 / 企业级软件（含 ERP）**：小红书获客。**差异化是本线的生死线，见第二节**

### 3. 月费线 —— 唯一能积累的收入结构

- **Google 评价管理**（= localrank，评价闭环+中文月报已开发完，Google API 审批暂停中，白标路径不受阻）
- **TikTok / Facebook 等代运营内容生成**（在评价管理之上加的第二个月费模块）
- 月费的本质：把一次性的建站客户沉淀成每月付费的长期客户

## 二、建站/系统线的差异化（用户定义，全文照录其逻辑）

中小企业不知道自己需要什么网站、什么系统，它只知道「我想线上宣传」「我想获客」「我要个门面」。
所以**绝不做「初级 299 / 中级 499」式的模板报价**——那样客户为什么不用模板、不用 AI 直接生成？

**打法：每一条线索，回给它的是一个针对这个行业、这个人、这个生意的咨询式定制 demo。**
先诊断（你这个生意在线上该长什么样），再给看得见的门面（demo），报价在诊断之后。

这恰好是一人+AI 公司才有的经济学：定制 demo 的边际成本≈token。
模板站给不了针对性，纯 AI 生成给不了诊断，传统咨询公司给不了这个价格和速度。
**能同时给三样的，目前只有这种打法。**

## 三、「AI 当 CEO」账号（CEO 对用户开放问题的决策）

**做，作为资产线第三个账号。** 对比过的两个方向：

| 方向 | 结论 |
|---|---|
| AI 当 CEO 运营实录 | ✅ 现在做。素材零成本自产（看板、台账、worklog 本身就是内容）；与职场/认知类内容 DNA 同源；市面叙事全是「人当 CEO 用 AI」，反着做有辨识度；喂课程线（这套运营法本身可以成为下一门课） |
| 成功案例账号 | ⏸ 不单开。冷启动死结——没攒够案例的案例号是空的。案例内容等真实交付攒到 3-5 个后，进建站获客的内容线里发，不独立开号 |

账号的诚实边界：运营实录必须是真的——数字取自台账，失败也发。造出来的实录会反噬全部三条线。

## 四、飞轮 v2

```
资产线内容（喜马拉雅+小红书+AI当CEO）
   ↓ 线索
职场咨询 + 建站/系统单（咨询式 demo 成交）→ 现金流
   ↓ 交付
案例与选题 回喂内容 ＋ 建站客户 沉淀为月费客户（评价管理/代运营）
   ↓
运营全过程本身 → AI当CEO账号素材 → 再引流
```

## 五、运营模型（不变）

git 台账唯一真相；判断闸门；拉动式流水线；工作日定时员工；财务封账冻结。
用户只做三件事：说想法、解锁阻塞、对外动作。

## 六、阶段目标（0–3 月）

- 资产线：三个账号全部周更不断（喜马拉雅扩容、小红书持续、AI当CEO 上线）；被动收入入账可见
- 现金流线：咨询式 demo 产线跑通，首个真实线索 ≤48h 出 demo；首单成交
- 月费线：3 个付费客户、MRR ≈ CAD $900（沿用 SaaS 台账阶段一判定）
- 获客：线索台账连续 4 周有新增

## 七、风险（v2 排序）

1. **获客未被证明**——不变，仍是第一
2. **咨询式 demo 的交付时间**——每单都定制，若单个 demo 超过数小时人时，模型不成立；必须产线化
3. 平台依赖（Google 审批 / 小红书 / 喜马拉雅政策）
4. 账号数据未接入视野——三个「不能停」的账号我一个都还看不见
5. 发散风险——判断闸门 + 冷藏区 + 本文档

## 八、融资立场（不变）

不融，设计使然。本公司投资人是用户的人时与 token 预算，路演材料是台账数字。
唯一例外路径：AI 运营系统本身被 6-12 个月 git 历史证明可复制——那是另一家公司的 BP，
而「AI当CEO」账号正在为那个可能性积累公开证据。
