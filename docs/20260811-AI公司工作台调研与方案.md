# 「AI 公司工作台」调研与方案

**日期**：2026-08-11
**起因**：用户看到短视频「完全不用发工资的AI公司真来了，SuperAICrew 直接把科幻片照进现实 #skill #codex #实体 #OPC #一人公司」，要求调研并搭一个这样的工作台
**状态**：调研完成，方案待用户拍板后进任务台账

---

## 一、调研结论（先说真话）

### 1. SuperAICrew 查无此物

GitHub、产品站、英文中文新闻源全查过，**没有叫 SuperAICrew 的产品或开源项目**。
名字几乎可以断定是蹭 **CrewAI**（真实存在、45k+ star 的多智能体框架）。
这类视频的套路：拿现成的多智能体框架/编排工具录一段 demo，起个大名，卖课或引流。
标签里的 #skill #codex 泄露了底细——大概率就是给 Claude/Codex 这类编码智能体配上技能和角色分工，包装成「AI 公司」。

### 2. 「不用发工资」是半真半假

- 真：没有人类雇员，没有社保工资单
- 假：**工资就是 token 和订阅费**。每个「AI 员工」每次上班都在烧钱，且不像人类员工会自己喊停。
  36 氪那篇讲得对：把 AI 员工当许愿池（全天候、零成本、啥都能干）是企业最常见的误区；
  真正能用的 AI 员工需要**明确职责、权限边界、工作流程和问责**——和管人一样，只是换了对象。

### 3. 这个赛道真实存在的东西

| 类别 | 代表 | 一句话评价 |
|---|---|---|
| 角色化多智能体框架 | **CrewAI**（role/goal/backstory + crew 编排）、LangGraph、Microsoft Agent Framework | 真东西，但要自己写 Python、自己搭运行环境、自己管记忆和成本 |
| 「AI 软件公司」模拟 | MetaGPT、ChatDev | 学术演示性质强，产出质量不稳定，不适合真业务 |
| 自治智能体平台 | SuperAGI 等 | 2023 一波 AutoGPT 热的延续，无人值守跑真业务的案例极少 |
| 工作流编排 + AI 节点 | n8n / Make / Dify | 适合「触发 → 处理 → 投递」的管道，不适合开放式工作 |
| **Claude Code 原生能力** | 子智能体、Workflow 编排、**Routines 定时会话**、Skills | **我们已经在用的这套**。云端会话可以定时自动醒来干活、写回 git |

### 4. 关键判断

**不引入任何新框架。** 理由：

1. CrewAI 们解决的问题——「让多个角色分工干活」——我们已经用更土但更可靠的方式解决了：
   **git 台账当任务队列 + Claude Code 会话当员工 + 回写 commit 当工作记录**。
   任务台账跑了 4 天、17 个任务、零失控，这套工作法本身就是别人视频里演的东西。
2. 新框架 = 新的运行环境、新的失败模式、新的记忆/成本管理问题，全是负债。
   我们缺的不是编排框架，是**三样东西**：员工的「花名册与岗位说明书」、**定时排班**（现在每个周期都要用户手动开工）、一个**看得见全局的工作台页面**。
3. 这三样，第一和第三是纯文件（我们最熟的模式），第二 Claude Code 云端 Routines 原生支持
   （cron 定时唤起会话，会话自己读台账、干活、提交、写日志）。

## 二、方案：Meridian AI 公司工作台

延续既有哲学：**git 是唯一真相；页面是生成产物；每个员工有红线和硬停止条件。**

### 架构（全部是文件 + 定时会话，无新增服务）

```
company/
├── roster.json          # 花名册：每个员工的角色、排班 cron、权限级别、状态
├── roles/               # 岗位说明书（= 每次定时会话的开工提示词）
│   ├── secretary.md     #   秘书：每天读任务台账+财务台账，出晨报，标阻塞
│   ├── accountant.md    #   会计：每周 roll/check，月初封账，异常报警
│   ├── researcher.md    #   调研员：每周盯竞品/渠道/政策变化，发现写回台账
│   └── engineer.md      #   工程师：读任务台账取第一个未完成条目开发（现有模式的固化）
├── worklog.jsonl        # 出勤与产出记录：谁、何时、干了什么、commit hash、花了多少 token
└── workbench.html       # 公司工作台（生成式，同 finance 模式）：
                         #   在岗员工 / 最近打卡 / 各台账健康度 / 阶段一目标 / 财务卡片
```

### 员工怎么「上班」

1. Routine 按 cron 唤起一个云端会话，开工提示词 = 该岗位的 `roles/*.md`
2. 会话读台账 → 干活 → 验证 → commit → 往 `worklog.jsonl` 追加一条打卡记录 → 重新生成工作台
3. 干不了/遇到红线 → 不硬来，把阻塞写进台账留给用户，这本身也算完成打卡

### 每个岗位说明书必含五节（这是和视频里玩具的本质区别）

职责（只干什么）／ 红线（绝不干什么，如：不碰客户 GBP、不对外发送任何东西、不花钱）／
硬停止条件（沿用台账规矩：同一问题失败 2 次就停）／ 产出物定义（没有产出物 = 没上班）／
预算（单次会话 token 上限意识，超了收工写遗留）

### 首批编制（建议，可砍）

| 员工 | 排班 | 干什么 | 为什么先雇 |
|---|---|---|---|
| 秘书 | 每工作日早 7 点 | 晨报：两本台账扫一遍，列今日可推进项+阻塞项+等用户决策项 | 解决「每次都要用户想现在该干嘛」 |
| 会计 | 每周一 + 每月 1 号 | `ledger roll/check`，月初封账，数字异常报警 | 财务台账已建好，正缺一个定时按按钮的人 |
| 工程师 | 按需（用户唤起）或每日一周期 | 台账取活干活回写，现有模式固化成岗位 | 已验证 4 天，直接转正 |
| 调研员 | 每周五 | GBP 政策/竞品/GTA 华人商家渠道扫描，发现写进台账「调研发现」 | 台账里 F1–F4 证明调研发现直接改变规划 |
| CEO | 不排班 | 用户对话的主会话：定方向、拍板、审员工的活 | 就是现在这个会话 |

### 成本（工资单）

按每员工每次会话粗估 5–20 万 token：秘书日更 + 会计周更 + 调研员周更 ≈
**每月百万级 token 量级**，在 Claude 订阅内。worklog 记录每次实际消耗，工作台上直接可见——
「不用发工资」的正确说法是**工资透明且按次可见**。

### 不做什么（同样重要）

- ❌ 不做员工之间实时对话协作（CrewAI 式）——员工通过 git 台账异步协作，可审计、可回放
- ❌ 不给任何定时员工对外权限（发邮件/发微信/碰客户资产）——对外动作永远过用户
- ❌ 不追求「全自动公司」叙事——追求的是：**用户每天只做决策和对外，例行动作全部消失**
